每行都是一个可以判定成败的场景。C01–C17 各用独立的合成账户。C18–C26 构成一次连续回放，同组共用一个账户与记忆库。按“输入及动作”操作，同时核对“预期”和“禁止结果”。例如删除后搜不到旧住址，还要检查另一条有独立来源的记忆仍在。表中记录的是预期行为，实际跑过的结果见本页末尾。[结构化样例](cases.json)

## 连续回放怎样执行（C18–C26）

按 S1 到 S9 顺序输入，统一采用上海时区。账户只授权测试用个人范围；除另有说明，每段开新会话，持久记忆跨段保留。普通步骤等待后台整理完再切换会话；S5 专测提交后、重算前的窗口。S8 的“刚才”指 S6 的选择，向三组提供相同的当轮问题上下文。时间表、距离和回执均为固定测试输入。

用同一模型、系统提示、当前对话、工具结果和输入顺序跑三组，每组从独立空库开始：关闭持久记忆、当前实现、候选方案。S4 的依赖夹具仅供支持该结构的实现验证传递失效，单独标为注入数据；比较自然生成与回答质量时不注入夹具，记录系统是否自行产生相关推断。旧实现缺少的能力标“未实现”。关闭记忆组只清除跨会话上下文，保留当轮完成任务所需信息。

逐轮记录四项：实际写入的性质与版本、检索到和最终送入模型的版本、助手回答或动作、出现的禁返内容。分别统计适用记忆用对数、不当个性化数、作废推断回流数，并报告各项分母和真机首字、首音频延迟。S5 与 S9 的禁返项出现一次即判相应用例失败。本次后端回放的观测和未覆盖项见[连续会话实测](verification/2026-11-18-koko-memory-replay.md)。

## 混合检索怎样验收（C27–C29）

在两套空库运行相同的 KoKo 连续会话。另建项目，用相同的 18 条记忆做改写对照。对每题检查问句与目标正文的词项交集为空，分别记录原问句检索名次、进入 KoKo 的名次和最终回答。保留确切编号和无答案问题作对照。额外用相同数据库关闭向量模型，单测降级效果。[实测结果](verification/2026-11-18-hybrid-retrieval.md)

## KoKo 选证据回归（C30）

固定候选顺序重放拿铁配料与湖畔订房错例。只有坚果记录时，拒答是正确结果；咖啡记录排第三时，拒答计为错误。湖畔的复合追问要求既说明本次推荐，也指出过去动机缺少依据。[最终模型复验](verification/2026-11-18-koko-evidence-selection.md)

## 邮箱账号与独立客户端（C31）

在空库注册一个所有者账号。A 写入原话，B 用另一种说法查询，检查当前版本及可见摘录；更正后由 B 再查，最后由所有者遗忘目标并重放 A 的旧来源。服务验收以权限、依据、版本和检索返回为准。[独立实测](verification/2026-11-18-standalone-email.md)

## 验证码及用户控制台（C32）

公网注册邮件已在腾讯企业邮收件箱核实；使用 ECS 上同版本的隔离实例，新收到的两封邮件均能完成校验。[真实收件与会话验收](verification/2026-11-19-aliyun-mail-inbox.md)

从注册页发送验证码，用错误码确认会被拒绝，再用邮件中的正确码进入控制台。退出后申请登录验证码，验证不能跨用途使用。新建项目、授权通用 MCP 客户端、兑换一次性接入码，并新增和修改一条记忆。[浏览器与邮件实测](verification/2026-11-19-email-console.md)

C31、C32 已使用独立外部邮箱、正式 HTTPS 入口和两个通用 MCP 客户端复核。KoKo 拿铁与湖畔两题分别记录服务端召回、本轮候选和最终回答。[公网验收记录](verification/2026-11-19-public-clients.md)

C10 的慢响应、真实读取失败和用户打断分别验收。KoKo 修正后，拿铁和湖畔各复测三次。[读取期限回归](verification/2026-11-19-koko-recall-deadline.md)

## 托管用户隔离（C33）

同一个 KoKo 实例接入两个邮箱账号和两条同名 Worker 连接，核对聊天、事实、任务及注销范围。[双账号公网结果](verification/2026-11-19-hosted-isolation.md)

## iPhone 原生记忆管理（C34、C35）

从 KoKo 设置输入邮箱验证码，核对三种时间、同名对象隔离、历史依据和更正结果。[云端与 iPhone 验收](verification/2026-11-19-koko-native-memory.md)

## 怎么复测

运行前固定样例版本和数据库快照。自动断言放入测试；涉及 KoKo 首字、首音频的用例，在同一设备和网络上采样。对无答案问题单列误召回，对权限和遗忘用例单列泄漏次数。按组给出正确数和总数，再报告延迟分位数。

每次运行在 verification 下按日期新增记录，写明用例和需求编号、代码提交、执行入口、设备、服务和模型版本。通过时附可复核的结果，失败时写实际行为和复现条件。功能尚未完成就标“待实现”，运行条件不足就标“未验证”。需求改动后更新预期，再用新记录报告结果。
