# 客户端接入协议


Go 服务的 Agent 协议包含两个操作，异步提交 `retain`，按需读取 `recall`。独立部署通过 MCP 提供，两者也可在宿主私有实例通过 HTTP 调用。源聊天由客户端管理。所有者控制台继续提供管理、纠错与遗忘。[工具定义](../internal/memory/tools.json)

## 自托管应用 API

一套私有实例服务一个宿主应用。宿主后端先验证自己的会话，再发送 `Authorization: Bearer <服务凭据>` 和 `X-Memory-Subject: <稳定账号 ID>`。这些头由后端构造。宿主既有连接需迁移时还发送旧项目 ID，旧库映射由运营方核对。密钥轮换保留原空间。未经授权返回 401，待迁移返回 409。私有监听口只对受信后端开放。

| 调用 | 行为 |
|---|---|
| GET /v1/app/projects | 返回本账号可管理的项目。 |
| GET、POST /v1/app/memories | 分页查记忆或新增；支持 q、project、state、category、entity、offset、order。 |
| GET、PUT、DELETE /v1/app/memories/{id} | 查实体及版本依据、按 revision 更正或遗忘。其他账号的 ID 返回 404。 |
| POST /v1/app/retain | 异步提交，HTTP 202 返回 operation_id。 |
| GET /v1/app/operations/{operation_id} | 用原应用身份查询提交进度。 |
| POST /v1/app/recall | HTTP 200，同一次请求返回本账号可读的证据。 |

应用请求由服务端确定项目，正文省略 project_id。独立 MCP 请求可以传已获准的项目，个人范围传 null。

### KoKo 原生客户端

KoKo 网页 /memory/ 和 iPhone 使用现有 KoKo 会话向 KoKo 请求 `/api/memory/projects`、`/api/memory/memories` 及条目详情。写请求携带 KoKo Origin。用户进入列表无需再次登录、绑定邮箱或输入服务地址。KoKo 返回 401 表示应用登录已失效；上游配置异常或不可达返回 503。

原生列表传 order=created 与 state=all；每页 50 条。详情返回当前实体、版本及 input_evidence。PUT 携带读到的 revision，确认推断时另传 confirm_statement=true。版本冲突应重新读取。聊天的写入及召回由 KoKo 后台完成。

旧托管模式的邮箱验证及 Agent 授权继续适用于已有客户端；独立控制台直接访问其 `/api/*`，沿用 Cookie、Origin 和 CSRF。应用模式不向手机签发 MemoSphere 所有者会话。

网页沿用 KoKo 的 HttpOnly Cookie，写请求接受同源校验。浏览器在记忆请求中发送 X-KoKo-Account 作为已打开页面的账号校验条件，服务始终用登录会话确定所有者。两者不一致时返回 412，页面重新核对登录状态；未登录返回 401。原生请求保持兼容。

KoKo 应用列表使用 order=created 时，同时返回 counts.all、counts.states、counts.categories，分别表示该所有者全部条数、各状态和各分类条数。缺少的状态计为零。total 和 items 仍对应本次筛选与分页。

Go 版独立 MCP 和应用接口使用同一套历史查询字段。

## 建立连接

所有者先在控制台填写邮箱、密码，再输入注册邮件中的验证码。已有账号使用登录验证码。创建项目后，为每个助理单独建立连接，选定项目和读写范围。客户端用一次性接入码换取自己的 Agent Key，后续调用只携带自己的 Key。一个账号可以授权多个助理，也可以单独轮换密钥或撤销其中一个连接。使用 Streamable HTTP 连接服务根地址下的 `/mcp/`，请求携带 `Authorization: Bearer <Agent Key>`。只有回环地址可用明文 HTTP。初始化 MCP 会话后先列举工具，再调用。

### 浏览器账号 API

控制台先调用 POST /api/auth/code，提交 email、password、purpose（register 或 login）。发信成功返回 expires_in 和 resend_after，单位均为秒。再调用 POST /api/auth/register 或 /api/auth/login，提交 email、password 和字符串 code，保留开头的零。两个步骤都要求同源 Origin。成功后的浏览器使用 HttpOnly 会话和 CSRF 字段。验证码校验失败返回 400，发送过频返回 429，邮件通道不可用返回 503。

通用 MCP 客户端的授权页会显示 MCP 地址及一次性接入码。客户端向 POST /api/connect/exchange 提交 code 字段换取 key。邮箱验证码仅用于用户注册和登录。

## 异步提交

`retain` 接受同一会话内按顺序提交的 1–64 条来源，async 默认 true。每条有稳定 source_id、role、text，可选带时区的 spoken_at 和 sensitive。建议重试沿用相同 request_id。应用 HTTP 示例：

```json
{"async":true,"request_id":"trip-batch-17","session_id":"trip","messages":[{"source_id":"17","role":"user","text":"我订了杭州湖畔酒店。","spoken_at":"2026-11-17T20:00:00+08:00"}]}
```

持久化后返回形如 `{"operation_id":"49d38ffc-ae5a-4275-879d-97a8c7b20217","status":"pending","item_count":1}`。独立客户端使用同一 Agent Key 查询 `GET /v1/operations/{operation_id}`，也可向 MCP 原样重发 retain。请求标识作用于所有者和连接。同标识异文冲突；相同来源出现在重叠批次也只对应一个整理作业。一批内任一输入冲突，整次接收事务回滚。遗忘后的来源重发会被删除记录拦截。

pending 和 processing 表示排队、执行或退避。completed 表示本批有效版本已提交，随后查询可读到当前事实，过时绑定退出当前结果。服务保留被忽略、已遗忘来源的语义；完成回执不保证每条发言都会成为事实。failed 和 cancelled 表示终态。权限变更后重新鉴权。任务状态属于该次 retain 的回执。查询不会等待其他批次完成，向量尚在回填时会标出降级。

## 按需召回

```json
{"query":"我订了哪家酒店？","max_tokens":1000}
```

默认 purpose 为 cite，terms 可省略。按相关性装入最多五条候选；max_tokens 默认 4096，允许 0–65536，以 cl100k_base 计算序列化 memories 数组的证据预算，包括摘录与版本字段。超出预算的完整候选会跳过。matched、no_match、needs_clarification、budget_exhausted 区分有据、无匹配、对象歧义和预算不足。传输失败保留错误状态。KoKo 负责最终回答。

### 混合检索参数

Go 版 recall 支持可选布尔值 `local_only`。调用方将不得外发的问句标记为 true，服务跳过远程向量编码，继续在授权范围内检索。本机 BGE 仍可编码。百炼模式下未标记的普通问句会发给配置好的北京业务空间。切换索引后，可从 `retrieval.model` 和 `retrieval.degraded` 核对当前模型及回填进度。

`entity_ids` 和 `entity_names` 只在明确限制对象时传，多个对象取交集。同名只在授权范围内消歧。可见名字对应多个 ID 时，返回空候选、`status=needs_clarification` 和备选 ID。一般问句里的对象作为软线索。所有者可在记忆写入时用 entities 提供名称、类型、别名及可选的稳定 UUID。跨记忆确认同一对象时复用其 ID。自动整理仅接纳与该条依据逐字相符的专名，同名且缺少辨认依据时保留独立 ID。可用 qualifier 提供城市等限定词。Go 服务对明确的同名歧义返回 unresolved[].options，其中只有当前调用方可见的名称。

`event_from`、`event_to` 是包含端点的发生日期，格式 YYYY-MM-DD。只有事件区间与筛选区间重合才返回。可用 `recent_progress` 明确控制近期权重。未传时按问句判断。可传 `as_of` 指定参考日，默认取服务所在时区的当天。问“上周”按该参考日前一完整自然周筛选。

查“2026 年 4 月 15 日我住哪”时，应用可发送以下请求。MCP 调用另传已授权的 project_id。

```json
{"purpose":"cite","query":"我住在哪个城市","terms":["住址","居住"],"valid_at":"2026-04-15"}
```

`valid_at` 指事实有效日。`known_at` 可选，指定知识截止时刻，接受带时区的 RFC3339 或东八区日期末。只给 known_at 时也按该日期查询事实。只给 valid_at 时使用今天掌握的证据。历史候选带 validity，其中 valid_from 与 valid_from_latest 表示起点范围，valid_to_exclusive 是已确定的结束日；只知结束范围时读 valid_to_earliest 和 valid_to_latest。known_from 与 known_until 使用 Unix 秒。日期依据不足时返回空候选。历史分支在 retrieval.degraded 标出 historical_lexical。

每条候选带 `entity_ids` 和 `ranking`，其中 ranks 为命中通道的名次，rrf 为基础分，time_factor 为时间系数，score 为最终分。可解析时间另有 event_interval 和 event_precision。顶层 retrieval 含模式、状态及 degraded。可能的降级原因包括 semantic_unavailable、semantic_index_incomplete、bm25_unavailable。接口示例为“只查星图项目十一月的订房进展”。

```json
{"project_id":"已授权项目ID","purpose":"cite","terms":["订房"],"query":"星图最近的订房进展","entity_names":["星图"],"event_from":"2026-11-01","event_to":"2026-11-18","as_of":"2026-11-18"}
```

## KoKo 怎样使用依据

recall 只返回已生效的用户陈述和工具观察，排除待核实的旧记录、待确认的推断和重算中的版本。共享事实可按授权读取，逐字引述还要求是本连接可读的原话。KoKo 在需要个人条件做选择时用 select，追问往事或依据时用 cite，普通时刻表计算用 skip。cite 返回的是候选。KoKo 核对本轮对象、所问属性和可引用的来源片段，再决定引用哪一条。对历史动机还要核对具体事件。KoKo 对一次读取最多等待 2 秒。超时、调用失败或不符合协议的响应表示历史无法核实；正常返回的空 memories 数组表示本次没有匹配。若同时追问上轮推荐与过去经历，可引用本会话的上轮建议，并单独说明历史未能核实。普通任务继续使用本轮输入。

通用客户端可用 tools/list 查看可用工具。用户要求遗忘时，首期引导用户进入所有者控制台确认。KoKo 真机上线前，按重复投递、跨连接读取、来源权限和删除重放逐项验收。[验收样例](验收样例.md)

## 消费分类目录（R18）

`GET /v1/app/memories?order=created` 返回 `category_catalog`，每项含 `id`、`label`、`description`。目录即使在空库中也包含五项。旧字段 `category` 继续返回中文名称；`category_id` 用于程序判断。筛选 `category=rule` 与 `category=规则` 等效。老数据里的“未分类”只在涉及该所有者的筛选项中出现，ID 为空，详情保留旧名称。

新增可提交 `{"text":"本次差旅每晚最多六百元","category_id":"rule"}`。仅调整类别时 PUT 原条目，提交 `{"revision":2,"category_id":"event"}`。成功后返回同一 ID 的新版本及原依据。版本过期、无效类别或试图直接将推断改为规则，均返回 400。KoKo 沿用同一账号的 `/api/memory/memories` 代理。混合召回条目附带 `category_id` 和 `ranking.category_factor`。
